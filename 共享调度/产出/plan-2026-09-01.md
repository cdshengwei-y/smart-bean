# 2026-09-01 日清夜跑计划

## 唯一目标

核查“智能录音豆”iOS App 1.0 被 App Store Review 拒绝的具体原因；仅针对审核详情中有证据的拒绝项准备可本地验证的修复或补充材料，并形成一次人工重新提交方案。

## 背景

- 2026-09-01 协商结果记录了用户确认的唯一目标，截图仅显示审核项 `2.1.0 Performance: App Completeness`。
- 当前未提供 App Review 的完整说明、复现步骤、测试设备和系统版本、账号或网络条件；这些信息不足以判定具体拒绝根因。
- 项目 iOS 原生应用使用 SwiftUI、CoreBluetooth、URLSession 与 Bonjour；现有 README 表明 BLE、Bonjour、WAV 下载和 OTA 需要 iPhone 真机验证，且需要开发者 Team 签名。

## 范围

1. 获取并逐条整理 App Store Connect 的完整 App Review 说明、复现路径与审核环境要求。
2. 将每一条审核明示问题关联到当前 iOS 代码、Info.plist、版本元数据或审核材料，区分已证实事实、代码定位和待验证假设。
3. 仅对可在本地验证的问题准备最小修复、回归验证方案或 App Review Notes、测试账号/演示路径等补充材料。
4. 输出人工重新提交清单，包括修复范围、版本/构建号策略、审核备注、元数据和提交前检查项。

## 非目标

- 不根据 `2.1.0` 标签猜测具体故障、伪造审核环境复现或宣称已经通过审核。
- 不自动在 App Store Connect 操作“更新审核”、重新提交或修改线上配置。
- 不连接生产服务、不读取真实用户数据、不烧录或操作真实硬件。
- 不对业务项目执行 Git 提交或推送；项目根目录当前不是 Git 仓库。
- 不扩展到与审核拒绝无关的功能重构。

## 执行者1-4分工

1. 执行者1：整理审核详情原文、复现步骤、设备/系统、账号及网络条件；缺失项逐条列为阻塞。
2. 执行者2：只读核查 iOS 工程的入口、权限声明、启动与网络相关配置，建立“审核问题—代码/配置”映射。
3. 执行者3：对每个有明确证据的项准备最小本地修复或补充材料，并记录可执行的本地验证步骤和 N/A 边界。
4. 执行者4：复核证据链、修复/材料清单和人工重新提交门槛，确保不把本地验证写成真实审核通过。

## 依赖顺序

1. 先取得完整 App Review 详情；没有详情不得对拒绝根因下结论。
2. 再读取相关代码、Info.plist 与版本资料，完成问题映射。
3. 仅对映射成立的项目进行本地修复或材料准备，并执行相应本地验证。
4. 最后由执行者4复核，形成供人工在 App Store Connect 中重新提交的清单。

## 约束

- 审核员明示内容、代码可证实事实和假设必须分开记录。
- 模拟器或静态检查只能证明本地范围；涉及登录、网络、BLE、Bonjour、下载、OTA 或审核环境的结论必须标注真实环境 N/A 或等待人工验证。
- 任何需要真实 iPhone、开发者 Team、审核账号或线上环境的验证，均不由软件执行者冒充完成。
- 执行者只在各自会话回传状态、已读输入、证据、修改文件、测试命令与结果、N/A/阻塞项、下一步和绝对截止时间；调度者统一更新共享文件。

## 测试

- 审核详情完整性检查：确认每条问题均含原文或明确标记缺失。
- iOS 配置静态检查：核查 `Info.plist` 中蓝牙、本地网络与 Bonjour 相关权限声明；仅记录当前事实。
- 对有明确问题的修改执行对应单元测试、构建或模拟器验证；未具备命令、签名、账号、真机或服务条件的项目标记 N/A。
- 材料自检：审核问题、代码定位、验证证据、App Review Notes 与重提清单一一对应。
- 修改前后执行 `git diff --check`（仅在实际存在 Git 工作区时）；当前业务项目根目录非 Git 仓库，此项 N/A。

## 验收标准

- 输出逐条拒绝原因分析，且每条均能追溯至完整 App Review 说明；无详情时明确阻塞，不给出根因结论。
- 每一个有证据的本地修复或材料项都附对应验证结果或 N/A 原因。
- 重新提交清单覆盖版本/构建号、审核备注、测试账号/演示路径（如需要）、截图/元数据与人工提交门槛。
- 真实审核环境、真机或服务依赖未验证时，不得标注整轮 PASS 或“审核问题已解决”。

## 停止条件

- 未提供完整 App Review 详情、复现步骤或必要审核环境信息。
- 所谓修复需要连接生产服务、真实用户数据、未授权账号、线上配置变更或自动重新提交。
- 无法区分 Apple 明示事实、代码证据与待验证假设。
- 人工负责人、绝对截止时间或必要实机条件缺失时，停止将该部分列为可执行验收。
