## 范围

- 梳理启动、网络/TLS、认证、模型服务、子进程和队列阶段的无进度超时路径。
- 固化失败终态的阶段、脱敏原因、任务 ID、超时类型和显式 `changedFiles` 记录。
- 使用本地 fixture/单测覆盖各失败阶段、无变更与有变更边界，并复跑现有失败、取消、通知重试回归。

- 不执行真实生产任务，不操作真实用户数据、真实硬件或生产服务，不发送业务测试消息。
- 不提交业务项目 Git、不推送、不创建 PR、不部署、不迁移数据库、不修改线上配置。

## 执行者1-4分工

1. 执行者1：梳理无进度超时路径，固化阶段判定、脱敏诊断和 `changedFiles` 合同。
2. 执行者2：补齐失败终态落盘与查询回读，覆盖无变更显式 `[]` 及有变更文件清单。
3. 执行者3：编写各失败阶段的本地 fixture/回归测试，验证正常完成、失败、取消和通知重试不回归。
4. 执行者4：独立审计状态机语义、证据完整性和停止条件，仅在任务会话回传。

## 依赖顺序

1. 先读取协商结果、现有状态机、任务存储和上一轮回传。
2. 固化失败诊断与 `changedFiles` 合同，再实现终态落盘和查询。
3. 完成本地 fixture/定向测试后，由执行者4独立终审并汇总 N/A/阻塞。

## 约束

- 诊断只记录必要的脱敏上下文，不泄露令牌、认证信息、真实用户数据或完整环境配置。
- `changedFiles` 必须来自受控采集；无变更也要显式保存空数组，不能依赖终端文本推断。
- 执行者只在各自任务会话回传，调度者统一落盘共享文件；真实外部链路与本地结果分开记录。
- 本地测试通过不等于真实飞书/Codex 链路通过。

## 测试

- 运行诊断、任务存储、失败报告和状态机相关定向测试。
- `node --test --experimental-strip-types test/*.test.ts`（若目标项目提供该入口）。
- `node --experimental-strip-types scripts/doctor.ts` 与 `node --experimental-strip-types src/cli/simulate.ts`（若入口存在）。
- `git diff --check`、`git status --short` 仅检查，不提交业务项目。

## 验收标准

- 每个失败任务可回读失败阶段、脱敏原因、超时/失败类型、任务 ID 和 `changedFiles`；180 秒无进度不再是无上下文错误。
- 无文件变更的失败任务显式保存 `changedFiles: []`；有变更时保存可回读的受控文件清单。
- 启动、网络/TLS、认证、模型服务、子进程、队列六类 fixture 有实际测试证据；失败、取消、正常完成和通知重试语义不回归。
- 真实飞书/Codex 链路无单独授权或证据时标记 `N/A`，不升级为 PASS。

## 停止条件

- 需求扩大为真实飞书测试、生产操作、批量重试、硬件或业务项目 Git 操作。
- 无法保存任务状态、幂等键或失败上下文，或重试可能产生未知外部副作用。
- 任一本地门禁失败、发现敏感数据泄露风险，或恢复会覆盖现有任务记录。
