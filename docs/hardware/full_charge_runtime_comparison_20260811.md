# 满电后使用时长对比表

日期：2026-08-11

对象：`bean_ye_2` 原XIAO主板 + 新扩展板

电池基准：项目当前采购/设计记录为 `3.7V LiPo 500mAh`。

计算口径：

- 理论时长：`500mAh / 平均电流mA`
- 保守时长：按可用容量 `400mAh` 估算，用于考虑升压/稳压损耗、低电压截止、电池老化和温度影响
- 当前没有可信的整机深睡电流、连续录音电流、上传电流实测值，因此不填写未经实测的固定续航数值

## 按模式估算

| 使用模式 | 旧方案/迁移前 | 新扩展板/迁移后 | 满电理论时长 | 满电保守时长 | 当前结论 |
| --- | --- | --- | ---: | ---: | --- |
| 深睡/长期待机，仅看已知可移除TF分支 | TF/storage分支曾记录约`40mA`仍挂载时会成为明显耗电项 | GPIO40关TPS22919，深睡时TF电源实测`0.017V`，该分支已关断 | 旧方案仅这一路就约`12.5h`；新方案该40mA负载已移除 | 旧方案仅这一路约`10h`；新方案该40mA负载已移除 | 新板待机续航优势最大，但整机最终待机时长还要补测整机深睡电流 |
| 深睡/长期待机，整机真实时长 | 旧整机深睡电流未形成当前基线 | 新整机深睡电流未测；TF断电已验证 | `500 / I_sleep_new`小时 | `400 / I_sleep_new`小时 | 需要USB-C电流表/功率计/实验电源补测；不能编数值 |
| 连续录音，不上传 | TF卡和麦克风都必须工作 | TF卡和麦克风仍必须工作，TF电源开关不会在录音中关闭 | `500 / I_record`小时 | `400 / I_record`小时 | 新板主要提升可靠断电和待机，不会凭空大幅提升连续录音时长 |
| 录音后立即Wi-Fi上传 | Wi-Fi、TF卡、CPU都工作，通常是高耗电模式 | 同样需要Wi-Fi、TF卡、CPU工作 | `500 / I_upload_avg`小时等效工作时间 | `400 / I_upload_avg`小时等效工作时间 | 需要实测；新板TF开关对上传时长帮助有限，因为上传时TF必须上电 |
| 典型一天间歇使用：少量录音 + 其余深睡 | 旧方案如果TF/storage分支不能关断，待机部分会持续吃掉容量 | 新方案录音结束后可进深睡并关TF，间歇场景收益明显 | 见下方组合公式 | 见下方组合公式 | 这是新板最有价值的使用场景 |

## 典型混合使用公式

| 场景 | 每天用量假设 | 每天耗电计算 | 满电可用天数 |
| --- | --- | --- | --- |
| 纯待机 | 全天深睡 | `24 * I_sleep` mAh/天 | `500 / (24 * I_sleep)` |
| 每天录音30分钟 | `0.5h`录音 + `23.5h`深睡 | `0.5 * I_record + 23.5 * I_sleep` mAh/天 | `500 / 每天耗电` |
| 每天录音1小时 | `1h`录音 + `23h`深睡 | `1 * I_record + 23 * I_sleep` mAh/天 | `500 / 每天耗电` |
| 每天录音2小时 | `2h`录音 + `22h`深睡 | `2 * I_record + 22 * I_sleep` mAh/天 | `500 / 每天耗电` |
| 录完立刻上传 | 录音耗电 + 上传耗电 + 剩余深睡 | `T_record * I_record + T_upload * I_upload + T_sleep * I_sleep` | `500 / 每天耗电` |

## 当前可以确认的续航优势

| 项目 | 结论 |
| --- | --- |
| 新板最确定的收益 | 深睡/间歇使用。TF电源已经实测关断到`0.017V`，旧方案中约`40mA`的TF/storage分支不再持续消耗电池 |
| 连续录音时长 | 不能只因为换新板就写大幅提升；录音时TF和麦克风必须工作，真实时长取决于整机录音平均电流 |
| 上传时长 | Wi-Fi上传是高耗电状态，新板TF电源开关在上传时不能关闭，因此上传续航仍需实测 |
| 满电后最终可用多久 | 需要补3个电流：`I_sleep_new`、`I_record`、`I_upload_avg` |

## 建议补测记录

| 参数 | 必要性 | 记录格式 |
| --- | --- | --- |
| `I_sleep_new` | 决定满电待机天数，也是新板最大优势 | 供电方式、仪表、接法、深睡后稳定电流 |
| `I_record` | 决定满电连续录音小时数 | 录音中，BLE连接状态，Wi-Fi状态，TF卡型号 |
| `I_upload_avg` | 决定录完上传时的电量损耗 | 上传同一文件大小时的平均电流和持续时间 |

当前只有万用表时，优先不要强行串表测整机电流；这会引入接触不稳、压降、保险丝量程和供电路径问题。等有USB-C电流表/功率计、实验电源，或做专门电池串联夹具后再补。
