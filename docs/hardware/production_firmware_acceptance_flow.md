# 新扩展板正式固件验收流程

本流程用于新扩展板通过独立硬件自检后，验证正式录音固件、Flutter App、TF卡、网络上传、转写和低功耗链路。对应记录表为 `docs/hardware/board_arrival_acceptance_record.md`。

## 1. 验收边界

- 正式固件工程：`firmware/esp32s3_recorder/`
- 硬件自检工程：`firmware/esp32s3_hardware_self_test/`
- 控制方式：Flutter App通过BLE开始/停止录音；本版不使用扩展板物理录音按键。
- CN1 Pad1在扩展板侧为NC，不参与正式功能。
- SD_CS固定为CN1 Pad28对应的D2/GPIO3；SD_PWR_EN固定为GPIO40。
- 电池百分比当前返回`-1`，本版没有电池电压采样电路，不把电量百分比列为验收项。

## 2. 工具和前置条件

- 通过数据传输验证的USB-C线。
- 已格式化为FAT32的测试TF卡；重要数据已备份。
- 万用表；有条件时使用带限流功能的电源进行首次上电。
- Android测试手机和烧录包内当前Flutter版AI Recording Bean App。
- 可用的2.4GHz Wi-Fi或手机热点。
- 可访问的MinIO、转写服务和Obsidian同步环境。
- 115200波特率串口监视器。
- 已填写`firmware/esp32s3_recorder/src/device_config.h`。当前XIAO主板必须继续识别为`bean_ye_2`；只有更换主板时才生成新的eFuse身份。

不要把真实Wi-Fi或MinIO密钥写入验收记录、截图或提交到版本库。

## 3. 阶段一：硬件自检门槛

1. 按到板记录表完成外观和未上电检查。
2. 在XIAO未连接扩展板时烧录自检固件。
3. 完全断电后插合扩展板，插入FAT32 TF卡。
4. 上电运行自动测试`A`，在麦克风测试的3秒内讲话或轻敲麦克风附近。
5. 输入`C`完成50次TF断电重挂载，必须为50/50。
6. 分别输入`0`和`1`，测量VCC_SD_3V3关断和开启电压。
7. 最后输入`0`并断电。

只有未上电检查、自检自动项目、50次循环和TF电源测量均合格，才能进入正式固件测试。

## 4. 阶段二：构建和烧录正式固件

推荐双击`firmware/board_bringup_package/board_bringup.command`，先选择`4`烧录正式固件，再选择`5`采集正式固件启动日志。脚本会校验固件SHA-256，并记录实际固件版本、device_id和外设初始化结果。

需要手动构建时，在正式固件目录执行：

```bash
cd firmware/esp32s3_recorder
RECORDER_ENV=xiao_esp32s3_custom_board_release_038
pio run -e "$RECORDER_ENV"
pio run -e "$RECORDER_ENV" --target upload
pio device monitor --baud 115200
```

本次只更换扩展板，不更换XIAO主板，所以正式启动必须显示`device ID: bean_ye_2`，不能再生成`bean-F865DF90A994`。记录环境名、启动日志中的实际device_id、固件版本和生成固件的SHA-256。

启动串口应确认：

- 出现`AI Recording Bean booting...`，没有持续重启。
- `microSD: ready`。
- `microphone: ready`。
- `microphone PDM channel: right`。
- `hardware profile: custom expansion board; TF power switch: GPIO40 active-high`。
- 出现BLE已就绪信息。
- 云端配置完整时进入后台联网；配置缺失时只允许进入恢复热点，不能把此状态误判为上传成功。

任一外设显示ERROR时停止正式功能测试，保存完整串口日志，重新使用自检固件定位。

## 5. 阶段三：BLE和短录音

1. 打开Android App，扫描名称以`AI Recording Bean`开头的设备。
2. 核对App显示的device_id与记录表一致后连接。
3. 开始一段10至20秒录音，同时正常讲话、轻声讲话并在麦克风附近轻敲一次。
4. 确认App状态变为录音中、计时持续增加、文件名不为空。
5. 点击停止，确认状态恢复为空闲且生成一个完成的`.wav`文件。
6. 连续做3次短录音，确认不存在第二次无法开始、无法停止、重复触发或文件名覆盖。

合格条件：BLE连接稳定，录音状态与操作一致，每次停止后都生成独立WAV。

## 6. 阶段四：WAV和麦克风质量

下载刚生成的测试WAV并检查：

- 文件可正常打开和播放。
- 格式为16kHz、16-bit、单声道PCM WAV。
- 播放时长与实际录音时长基本一致。
- 有可辨识人声，不是全静音、持续满幅噪声或周期性断续。
- 轻声、正常说话和轻敲的响度变化能够听出。
- 麦克风声孔未被PCB、焊锡、胶或外壳遮挡。

自检固件的麦克风PASS只证明电气数据存在，不能替代本节试听。

## 7. 阶段五：TF文件操作

1. 在App读取TF卡文件列表，确认3个测试WAV都存在，大小和时长合理。
2. 下载其中一个文件并与设备端文件名对应。
3. 删除一个专门创建的测试文件，再刷新列表确认已删除。
4. 不删除历史录音或非本次验收生成的文件。
5. 需要验证HTTP API时，先运行只读检查，再运行写入检查：

```bash
RECORDER_IP=192.168.4.1  # 按设备当前地址修改
python3 tests/device_smoke_test.py --device "$RECORDER_IP"
python3 tests/device_smoke_test.py --device "$RECORDER_IP" --allow-write
```

`--allow-write`只删除脚本自己创建的测试文件，不要在设备正在录音时运行。

## 8. 阶段六：离线录音和恢复上传

1. 暂时关闭设备使用的Wi-Fi或热点，保持BLE可用。
2. 通过App录制并停止一段测试音频。
3. 确认无网络时WAV仍保存在TF卡，上传失败不会删除本地文件。
4. 恢复2.4GHz网络，等待设备重新连接并补传。
5. 在MinIO确认对象位于`recordings/<device_id>/`，文件名和大小与设备一致。
6. 确认TF卡原WAV仍保留，并产生对应上传完成标记。
7. 确认后端完成转写，在`notes/<device_id>/`生成Markdown，并同步到该设备对应的Obsidian目录。

合格条件：断网不影响本地录音；恢复网络后自动补传；不同device_id的数据不串目录。

## 9. 阶段七：上传中断恢复

1. 录制至少3分钟，并确认WAV大于固件当前5MiB分片大小。
2. 上传开始后关闭网络，但不要切断整机电源或拔TF卡。
3. 确认WAV仍在TF卡，设备报告上传失败或等待重试。
4. 恢复网络，确认上传能够继续或安全地重新开始，最终MinIO对象可完整下载和播放。

该项用于验证上传恢复，不用于验证突然断电。不要同时引入两个故障变量。

## 10. 阶段八：录音中断电恢复

此项有FAT32写入中断风险，只在基础录音、TF读写和上传全部通过后进行，并使用已备份的测试TF卡。

1. 开始录音并持续至少10秒。
2. 切断整机USB或电池电源，不要直接拔出TF卡。
3. 重新上电并保存启动串口日志。
4. 固件应从`.wav.part`恢复文件头并生成可用`.wav`。
5. 下载并试听恢复文件，允许末尾丢失最后一次尚未刷入TF卡的短片段，其余内容应可播放。
6. 确认恢复文件之后还能继续新建录音和上传。

若TF文件系统损坏，立即保存现象和日志，不要反复格式化后声称测试通过。

## 11. 阶段九：空闲深睡和TF断电

首次测量可先烧录5秒强制休眠镜像，缩短等待：

```bash
cd firmware/esp32s3_recorder
pio run -e xiao_esp32s3_custom_board_force_sleep_test_038 --target upload
pio device monitor --baud 115200
```

看到`DEEP_SLEEP_POWER tf_switch=enabled tf_en=LOW mic_clk=LOW`后再测量。该镜像只用于电气诊断，测完必须重新烧录`xiao_esp32s3_custom_board_release_038`。

1. 确认没有BLE连接、没有录音、没有正在上传或待扫描任务。
2. 保持串口观察，等待默认约2分钟空闲时间。
3. 应出现进入深睡的串口提示，之后设备停止BLE广播。
4. 测量VCC_SD_3V3对GND，应接近0V。
5. 记录整机深睡电流、供电方式、测量仪表和测试接法。
6. 按Reset唤醒，确认TF重新挂载、BLE重新广播且历史文件仍存在。

首块板只建立电流基线，不使用未经实测验证的固定电流阈值。后续同批板可在首块合格基线基础上制定离群判定范围。

## 12. 阶段十：稳定性验收

1. 连续录音至少30分钟，期间保持设备静置并避免线缆松动。
2. 停止后确认WAV可完整播放、时长基本一致、文件头正确。
3. 再执行至少10轮短录音开始/停止，检查状态机和文件命名。
4. 重启设备，确认已完成录音仍存在，未上传文件能够继续补传。
5. 检查板上连接器、TF卡座和电源器件是否异常发热或接触不良。

## 13. 最终通过条件

正式固件验收通过必须同时满足：

- 到板记录表的未上电检查和自检项目通过。
- 正式固件启动时microSD和microphone均ready。
- BLE、短录音、WAV试听和TF文件操作通过。
- 离线录音、恢复上传、MinIO路径、转写和Obsidian同步通过。
- 30分钟连续录音和重启后文件保留通过。
- 深睡时TF电源能够关闭，并已记录整机电流基线。
- 所有失败项均有日志、测量值和处置结论，不以“偶尔成功一次”代替通过。

上传中断恢复和录音中断电恢复若因测试条件暂缓，必须在记录表中明确标记“未测”，不能标记为合格。
